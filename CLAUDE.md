# Библиотека — заметки для Claude

Домашняя электронная библиотека: книги (PDF, EPUB, DjVu, FB2, MOBI, AZW3, TXT), полки, читалка PDF, заметки и уроки. Владелец: Григорий (GitHub: Grisha-Kr). Пользователи: он и близкие, до 5 человек, регистрация по приглашению. Адрес: `https://knigi.grishaweb.ru`. Репозиторий открытый: **книги, тексты книг и файлы уроков в него не класть никогда**.

Устройство повторяет «Молитвенный дневник» (Grisha-Kr/molitva): приглашения, письма (правки 2.2), защищённые ссылки на файлы с кукой (правки 2.3), загрузка своим маршрутом, файлы вне `pb_data`.

Этапы. Этап 1 (сделан): книги, полки, загрузка, читалка PDF, заметки и уроки, файлы уроков, «Видна всем», извлечение текста PDF, подпись, журнал, ограничение скорости. Правки 1.1 (сделаны): заметка и урок на весь экран, подсказки у кнопок редактора, новый значок, фото профиля. Этап 2 (сделан): выделения в тексте цветом с мыслью (у читателей тоже), «Маркер» для телефона, читалка EPUB, одна карточка для нескольких форматов книги (объединить, добавить и убрать формат). Правки 2.2 (сделаны): отметки «Читаю» и «Прочитано», книги от читателей с проверкой, поиск в адресе, профиль по фото вместо пункта меню, маленькая кнопка загрузки. Этап 3 (сделан): группы чтения (лента цитат и заметок, комментарии, «Сегодня читали», неделя, план по желанию создателя), в интерфейсе слово «цитата» вместо «выделение». Правки 3.1 (сделаны): новые форматы (DjVu → PDF, FB2/MOBI/AZW3/TXT → EPUB, оригинал рядом), распознавание текста в сканах (OCR), `update.sh` перезапускает сам себя в новой версии. Этап 4 (сделан): удалённый сервер MCP для Claude, ChatGPT и Perplexity с входом OAuth (поиск книг, текст по страницам и разделам, поиск в тексте, заметки, заметки моих групп, новая заметка от ИИ), раздел «Подключение к ИИ» в профиле. Правки 4.1 (сделаны): скрытые книги (часть А), срок доступа читателей (часть Б). Правки 4.2 (сделаны): числа на вкладках карточки, «Назад» из карточки с одного нажатия, «Без подписи на страницах» у отдельного читателя. Правки 4.3 (сделаны): часть А, скрытая книга, открытая отдельным читателям; часть Б, аудио к книгам (главы, черновики, плеер, мини-плеер). Правки 4.4 (сделаны): часть А, условия пользования (редакции, окно при регистрации и у старых читателей, раздел «Условия»); часть Б, новые надписи о продлении и письмо с заполненной темой. Правки 4.5 (сделаны): часть А, сообщения администратору (темы, снимок экрана, ответы, архив, точки), поправка README про удаление аккаунта. Правки 4.6 (сделаны): отзывы о книгах (вкладка «Отзывы», «Новые отзывы» на главной, раздел «Отзывы» у администратора). Позже: выгрузка оригиналов с понятными именами.

## Общение с владельцем
- Только на русском. Английские слова сопровождать переводом в скобках.
- Владелец не программист: простыми словами, команды готовыми к вставке, по одной задаче, где выполнять (Mac или сервер).
- Без длинных тире, без эмодзи, без конструкций «не X, а Y», без пафоса и повторов.
- В интерфейсе сохранённое выделение текста называется **«цитата»** (вкладка «Цитаты», «Цитата сохранена», «Удалить цитату»). Слово «выделить» только для самого действия пальцем или мышью. В базе и коде остаётся `highlight`.
- Пароли нигде в коде и инструкциях не писать.

- `book_offers` (правки 2.2): user (каскадно), book (без каскада, пусто после отказа или удаления книги), title (обновляет хук после правки книги), file_name, file_size, note, status (pending/approved/rejected), reason, decided_at. Читает владелец и admin, пишет только сервер.

- `reading`: user, book, format, page, pages, pct (0–100), pos (EPUB CFI); уникальная тройка (user, book, format): прогресс у каждого формата свой. Для читалки PDF (pdf, djvu) page/pages, для читалки EPUB (epub, fb2, mobi, azw3, txt) pct и pos (page/pages = «локации» foliate, нужны журналу). Видит владелец, пишет только маршрут progress. Последний формат книги у человека = запись с самым свежим `updated`.

LIKE в SQLite не понимает регистр кириллицы), page, format (pdf/epub: в каком файле page или место), place (сервер чистит; «с. 45» или «Глава 3 · 41%»), shared, group (этап 3: relation на groups без каскада, пусто = личная), quote (до 20 000), anchor (json), color, created, updated. Видят владелец, все при shared и участники группы при group. shared и kind = lesson ставит только admin, highlight может любой (правила и хук `checkNote`). Вид highlight не меняется на note/lesson и обратно. У чужой записи anchor и color скрыты, если она не shared и не групповая. Подробно о выделениях (в интерфейсе «цитаты»): раздел «Выделения», о группах: раздел «Этап 3».
- `note_files`: note (каскадно), owner, name, ext, size, file (имя в FILES_DIR), sort. Создаёт только маршрут загрузки, удаляет владелец (хук после удаления убирает файл с диска, срабатывает и при каскаде от урока). - `ocr_jobs` (правки 3.1): book, file (оба каскадно), book_title, status (queued/running/done/error/canceled), pages, done_pages, sec_page, attempts, error, started_at, finished_at. Видит admin, пишет только сервер (convert_lib.js).
- `notes.format`, `group_plan.format`: те же семь форматов (цитата из DjVu: format djvu и page).
- `notes.ai` (этап 4): кто из помощников создал заметку («Claude», «ChatGPT», «Perplexity» или сайт). Ставит только сервер MCP; `checkNote` при правке через API оставляет прежнее значение, при создании ставит пусто.

## Текст книг (для этапа 3)
Текст лежит у каждого файла: `text/ID_ФАЙЛА.txt`. Основной текст книги: `text/<books.text_file>.txt` (PDF с текстом, иначе EPUB). У книг этапа 1 id файла = id книги.
- PDF (`pdfText`): вывод `pdftotext -enc UTF-8` разбит по `\f`, каждая страница начинается строкой `=== Страница N ===`, потом текст, пустая строка. N = номер страницы PDF (как в читалке и в `notes.page`). Пустые страницы тоже есть. `book_files.has_text` = страниц с текстом (не меньше 30 знаков без пробелов) не меньше 20%.
- EPUB (`epubText`): разделы в порядке чтения (spine), каждый начинается строкой `=== Раздел N: название ===` (название из оглавления nav/NCX, иначе из первого заголовка). Текст без тегов, абзацы через перевод строки. has_text = не меньше 500 знаков без пробелов.
- Файла нет, если текста нет.
- DjVu: переводится в PDF, спрятанный текст DjVu становится текстовым слоем PDF, дальше как у PDF (`=== Страница N ===`). FB2, MOBI, AZW3, TXT: переводятся в EPUB, текст как у EPUB.
- Распознанный скан: текст как у PDF, `book_files.ocr = true` (возможны ошибки). Основной текст книги (`syncBook`): PDF со своим текстом, иначе книга читалки EPUB, иначе DjVu со спрятанным текстом или распознанный скан.

## Логика на сервере (pb_hooks)
- `convert_lib.js` (правки 3.1): `VIEW`, `fmtOfName` (имя → формат и расширение оригинала), `runTool`, `kindleDrm`, `convert`, очередь распознавания (`ocrBook`, `ocrAll`, `ocrTick`, `ocrCancel`, `ocrCancelFile`, `ocrState`, `ocrPause`, `ocrCleanDirs`).
- `main.pb.js`: хуки и маршруты. `lib.js`: роли, авторы, полки, заметки (`cleanHtml`, `plainText`, `checkNote`), регистрация, письма. `files_lib.js`: папки, ключ, кука и ссылки, Range, лимит, журнал, загрузка частями, обработка, обложки, удаление книги. `groups.pb.js` и `groups_lib.js` (этап 3): группы, план, учёт чтения по дням, комментарии, групповые заметки. В обработчиках код верхнего уровня недоступен: `require(`${__hooks}/lib.js`)` внутри.
- Регистрация: первый `role=admin`, остальные по коду `invite`.
- **Загрузка** (admin): `POST /api/knigi/upload/start {name, size, kind: book|file, note, book}` (book = добавить формат к этой книге; второй файл того же формата отклоняется) → `{upload, chunk: 8 МБ, chunks}` (проверка расширения, размера: книга 500 МБ, файл урока 50 МБ, свободного места `size*2` против `MIN_FREE_GB`); `POST /api/knigi/upload/{up}/{n}` multipart `chunk` (размер куска проверяется, повтор перезаписывает); `POST .../finish` склеивает (`cat`) и создаёт `books` + `book_files` (status processing, название и авторы из имени «Автор - Название»), только `book_files` (новый формат) или `note_files`; ответ `{id: книга, file, kind}`; `DELETE /api/knigi/upload/{up}`. Куски по 8 МБ нужны, чтобы одна загрузка не упиралась во время одного запроса и не держала память.
- **Книги от читателей** (правки 2.2, `finishOffer`, `approveOffer`, `rejectOffer` в files_lib.js): `upload/start {kind: offer, note}` только не-администратору, `OFFER_MAX` = 3 (на проверке плюс загружаемые сейчас, проверка при start и finish); куски, finish и отмена загрузки offer разрешены владельцу загрузки. finish склеивает, считает sha256: совпал с файлом обычной книги → файл удаляется, ответ `{duplicate: {id, title}, message}`; с файлом книги на проверке → `{pending: true, message: «Эта книга уже на проверке.»}`; иначе books (pending, offered_by) + book_files (processing, hash) + book_offers, письмо администратору (`mailNewOffer`, не чаще раза в час по `mail_log.kind = offer`). `POST /api/knigi/process` доступен любому вошедшему (только запускает очередь). `POST /api/knigi/offers/{id}/approve {shelves}` (admin, не во время обработки, не при ошибке): pending false, файлы пересохраняются (живое обновление у читателей), полки только общие. `POST .../reject {reason}` (причина обязательна): offer rejected, книга удаляется `deleteBook` (файлы, текст, обложка, авторы без книг). Письма человеку `mailOfferDecision` (`offer_ok`, `offer_no`). Письма уходят, только если в настройках включён SMTP (`mailReady`, `GET /api/knigi/admin/mail`). Удаление книги на проверке из карточки ставит offer rejected «Администратор удалил книгу.».
- **Новые форматы** (правки 3.1): `upload/start` принимает pdf, epub, djvu/djv, fb2, fbz, fb2.zip, mobi, azw3, txt (FB2 и TXT до 200 МБ), формат по `fmtOfName`; файл ложится как `ID.<расширение оригинала>`. В `finish` у MOBI/AZW3 проверка защиты (`knigi_convert.py drm`: поле encryption записи 0 PalmDB, TPZ = Topaz): защищён → файл удаляется, 400 «Эта книга защищена Kindle, загрузите версию без защиты.» (и у offer). `processFile`: если `VIEW[format] != format`, `convert` из оригинала (`orig_file` или `file`) в `ID.pdf.part`/`ID.epub.part` → `ID.pdf`/`ID.epub`, file = он, orig_file = оригинал, ocr = false; дальше ветка PDF или EPUB. Название и авторы из EPUB-метаданных берутся и для FB2/MOBI/AZW3 (не для TXT: там имя файла «Автор - Название»).
  - DjVu (`cmd_djvu`): `djvudump` (размер, dpi, слои), маска `ddjvu -mode=mask` (600 dpi уменьшается до 300) → JBIG2 пачками по 16 страниц (`jbig2 -s -p -t 0.9`, общий словарь знаков как в DjVu), фон `-mode=background` в своём разрешении → JPEG 62, цвет текста усредняется по маске (одноцветный → трафарет `ImageMask`, иначе маленькая картинка с `/Mask`); у JBIG2Decode 0 = чёрное, Decode не ставить. Спрятанный текст: `djvused -u -e output-txt` → невидимый текст (режим 3, GlyphLessFont из `pdf.ttf` tesseract, Identity-H, ToUnicode), растяжка `Tz` по рамке слова. Оглавление `print-outline` → закладки PDF. Пачки склеивает `qpdf --empty --pages`. PDF выходит в 1-1,7 раза больше DjVu.
  - FB2 (`cmd_fb2`): UTF-8 проверяется первым (бывают файлы с windows-1251 в заголовке и UTF-8 внутри), иначе кодировка из заголовка; битый XML чинится (`&`), иначе `LooseTree`; разделы верхнего уровня = файлы (больше 150 тысяч знаков делятся по подразделам), примечания отдельным файлом, ссылки `@@id@@` переписываются на файл.
  - TXT (`cmd_txt`): UTF-8 (BOM, UTF-16), иначе лучшая из cp1251/koi8_r/cp866 по доле частых строчных русских букв; абзацы по пустым строкам или по строкам; главы по `HEAD_RE` (не меньше 2, в среднем не меньше 1500 знаков), иначе части по 40 тысяч; обложка `make_cover` (Literata, при латинице DejaVu).
  - MOBI/AZW3 (`cmd_mobi`): `mobi.extract`; KF8 даёт EPUB как есть, старый MOBI даёт HTML → `XhtmlWriter` (режет по `mbp:pagebreak`, заголовкам и каждые 80 тысяч знаков) → EPUB.
- **Распознавание** (правки 3.1, admin): `GET /api/knigi/ocr` → `{available, langs, sec_page, paused, scans: {count, pages}, jobs}` (у running ход из progress.json); `POST /api/knigi/books/{id}/ocr` (сканы книги: файлы читалки PDF, ready, без текста), `POST /api/knigi/ocr/all` (кроме книг на проверке), `POST /api/knigi/ocr/{id}/cancel`. Cron `knigi_ocr` раз в минуту и после этих маршрутов `ocrTick`: running с `result.json` → `finalize` (число страниц, `optimizePdf`, `pdfText`, переименование поверх `file`, has_text, ocr) или ошибка; процесс жив (pid из `.ocr/ID/pid`, его cmdline содержит id задания) → done_pages, sec_page; мёртв без результата → запуск снова (до 8 раз, `attempts`; готовые куски не пересчитываются); иначе следующий queued. Запуск `setsid -f sh -c '… nice -n 19 ionice -c 3 python3 knigi_convert.py ocr …'` (в той же службе: остановка службы останавливает и его, после запуска очередь продолжается). `cmd_ocr`: куски по 10 страниц `qpdf --pages`, `ocrmypdf.ocr(jobs=1, output_type=pdf, optimize=0, oversample=300, skip_text, pdf_renderer=sandwich, progress_bar=True, plugins=["ocr_progress"])`, затем у каждой страницы оригинала заменяются Contents и Resources (страница остаётся тем же объектом: оглавление и ссылки целы). Пока `processQueue` работает, распознавание на паузе (`kill -STOP` группы, потом `-CONT`). Отмена: `kill -TERM -- -PID`, папка удаляется, книга как была. Удаление книги, «Убрать формат» и «Обработать заново» отменяют распознавание файла. Замер (2 ядра, один поток): 6-8 с и до 130 МБ на страницу 300 dpi.
- **Обработка** (`processQueue`, `processFile`): блокировка через `$app.store().setFunc("kn_proc")` (брошенной считается через 6 часов: перевод большого DjVu долгий), по одному файлу, пока есть `book_files.status = processing`; после файла `syncBook`. Запуск: `POST /api/knigi/process` (приложение зовёт сразу после загрузки), cron `knigi_process` каждую минуту. PDF: sha256 исходника, `pdfinfo` (страницы, Title, Author; год не берётся), **`qpdf --object-streams=generate --stream-data=preserve`** (см. ниже), обложка `pdftoppm -scale-to-x 400 -jpeg`, текст. EPUB: `unzip -p` container.xml и OPF (title, creator, date, description, обложка → `fs.createThumb` 400x0), текст `epubText`. DjVu: `djvused -e n`, обложка через `ddjvu -format=pdf -page=1` + pdftoppm. Название и авторы из файла ставятся, только если файл у книги единственный, администратор не правил название и имя файла не вида «Автор - Название» (у EPUB свойства важнее). Год и описание, только если пусто. Обложка из файла, только если у книги её нет (обложку из файла делает только тогда). Ошибка → status error у файла, текст в status_note; «Обработать заново» = `POST /api/knigi/books/{id}/reprocess` (все файлы книги).
- **Почему qpdf**: в PDF без потоков объектов (ReportLab, ImageMagick, многие сканы) описание каждой страницы лежит рядом с её картинкой. pdf.js при открытии вызывает `checkLastPage` и при переходе на страницу N перебирает описания всех предыдущих страниц, то есть с загрузкой по кускам скачивает почти весь файл (проверено: 110 МБ при открытии). После `qpdf --object-streams=generate` открытие стоит 1,2 МБ, страница 150 тоже. Линеаризация (`--linearize`) не помогает. Если qpdf не справился, остаётся исходный файл и пометка в status_note.
- **Ссылки и кука** (как материалы «Молитвенного дневника»): `GET /api/knigi/session` ставит куку `kn_s` (JWT {u}, 12 ч, `Path=/api/knigi/f`, HttpOnly, SameSite=Strict, Secure при https/X-Forwarded-Proto). `GET /api/knigi/books/{id}/link?f=ФОРМАТ` (любой из семи, без f = pdf) → `{url, size, ttl, mark, chunk, file, format, view, whole}` и та же кука; ключ в адресе (JWT {k, i = id файла, u}, 2 ч). `GET /api/knigi/f/book/{id файла}?t=` проверяет ключ, куку и что человек один; для читалки PDF (pdf, djvu) **только Range, не больше 4 МБ** (`MAX_SPAN`), без Range 400; для читалки EPUB (epub, fb2, mobi, azw3, txt) без Range целиком (до `EPUB_MAX` = 100 МБ, весь размер идёт в лимит и журнал); у не-администратора лимит и журнал; заголовки no-store, octet-stream, inline. Файлы уроков: `GET /api/knigi/files/{id}/link`, `GET /api/knigi/f/file/{id}?t=` (PDF частями; `&dl=1` целиком только владельцу). Обложки: `GET /api/knigi/f/cover/{id}?v=имя` по куке, кэш браузера 30 дней (адрес меняется с обложкой). `POST /api/knigi/logout` стирает куку.
- **Лимит** (`takeBytes`): в памяти (`$app.store`, ключ `kn_rate:user`) два счётчика по часам, прошлый час учитывается долей; сверх `MAX_MB_PER_HOUR` ответ 429 `{message, wait}`. После перезапуска счёт с нуля. На admin не действует.

## Аудио в клиенте (правки 4.3, часть Б)
- Ключи `atracks` (audio_tracks, `sort,created`), `aprog` (свой audio_progress). `tracksOf`, `hasAudio`, `progOf`, `trackNew` («Новая»: опубликована после первого прослушивания этой книги и ещё не открыта), `audioNew`, `contTrack` (последняя начатая, иначе следующая, иначе первая недослушанная), `nextTrack`.

Сохранение раз в 10 с, при паузе, конце, смене главы, уходе со страницы (keepalive); `played` = реально прослушанные секунды. Дослушано (≤15 с или 98%) → done. Конец → следующая глава; ссылку на неё берёт заранее за 2 минуты до конца (`AP.next`), чтобы включиться при выключенном экране. Ошибка (ссылка старше 2 часов) → новая ссылка и то же место (`apError`, 2 попытки). Скорости `AU_RATES` 0,75–2, `kn_apRate`. Media Session: название главы, автор, книга, обложка, play/pause/seek/предыдущая/следующая, `setPositionState`.
- Экран `#/listen/ID_КНИГИ` (`VIEWS.listen`, ползунок `.ap-seek` не перерисовывается, пока его тянут: `AP.seeking`), мини-плеер `#mini` (`renderMini`, класс `has-mini` на html, скрыт на экране плеера, в читалке и «на весь экран»), карточка: `listenBtn`, `audioBlock`, `trackRow` (у admin «⋯» `audioMenu`: опубликовать, переименовать, заменить файл, выше, ниже, удалить), `audioAdd` (окно новой главы: название, место, файл, длительность из браузера `fileDuration`), `audioBookForm` («Добавить книги» → «Аудиокнига без текста»), главная `contListenHTML`, значок `audioMark` на обложке, фильтр `UI.booksAudio`, журнал «слушал N мин» и главы, профиль «Глав аудио». Загрузка глав через ту же очередь `UP` (kind audio, `extra`). Без доступа (`readOnly`) кнопки глав выключены, на экране плеера `roNote`.

## Этап 2: выделения, EPUB, форматы
- **Почему выделения в `notes`**: у заметок уже есть владелец и права, «Видна всем», поиск, раздел «Заметки», «Заметки автора библиотеки»; этап 3 читает одну коллекцию. Выделение = `kind: "highlight"`, quote (выделенный текст целиком), color (yellow/green/blue/pink, `HL` в app.js, `HL_COLORS` в lib.js), body/body_text (мысль), book, format, page (у PDF), place, anchor:
  - PDF: `{v: 1, rects: [[x, y, w, h], …], s, e}`: прямоугольники в долях ширины и высоты страницы (не зависят от масштаба и экрана; куски одной строки склеены, `rangeRects`), s и e: номера первой и последней буквы в тексте страницы pdf.js (`tlRangeText`). Выделение всегда на одной странице: на экране одна страница, продолжение на следующей = отдельное выделение.
  - EPUB: `{v: 1, cfi, pct, chapter}`: место EPUB CFI (foliate `view.getCFI`), процент и глава на момент выделения.
- PDF (`RD.hls`, `rdLoadHls`, `rdDrawHls`): свои выделения книги в формате pdf, слой `.hl-layer` между холстом и текстовым слоем (`mix-blend-mode: multiply`, в «Тёмных страницах» screen), `.hl-tmp` для временной подсветки. Мышь: после отпускания `rdSelCheck` → панель. Нажатие по выделению (`rdHitHl`) → панель правки. Мигание `rdFlash` (класс `.flash`).
- **Панель** `#hl-pop` (`hpShow`, `HP`, `hpAction`): новая: 4 цвета, «Заметка» (жёлтое + окно мысли), у admin «Копировать»; готовая: цвета, «Мысль», удалить (`arm`), «⋯» → «Сделать заметкой» (`hlToNote`: новая заметка с цитатой и местом, выделение остаётся), «Настройки» (admin, «Видна всем»), «Удалить». Нажатие мимо панели только закрывает её (`HP.eat`). Общие выделения администратора у читателей не рисуются, только в списках.
- **Выделение в EPUB на телефоне** (правки после этапа 2): foliate листает EPUB, сдвигая ленту страниц за пальцем, и не знает о выделении. Поэтому, пока на странице есть выделение или включён «Маркер», обработчик `guard` (capture на touchstart/move/end/cancel в документе главы) не пускает касания к foliate: палец и ручки двигают только выделение. Место страницы (`renderer.start`) запоминается в начале такого касания (`EP.hold`) и после отпускания восстанавливается (`epHoldPage`: `scrollBy` на разницу, при неровности `snap`). Касания пальцем (pointerType не mouse) не доходят до foliate как pointerdown/pointerup, иначе он сам листает, когда выделение тянут к краю. PDF: при выделении свайп не листает (`TP.sel`). Ширину колонок и отступы foliate не трогать: при обычном чтении на iPhone страница стоит ровно.
- **Панели читалки**: нажатие в середину страницы прячет и показывает верхнюю и нижнюю панели (`toggleBars`, первые 3 раза подсказка `kn_barsHint`); при каждом открытии книги панели видны (`rdOpenScreen`); при первом открытии EPUB подсказка про середину страницы и «Маркер» (`kn_epHint`). Панель выделения (`hpShow`): выделение в верхней половине экрана, панель под ним; в нижней, над ним (на телефоне отступ 26px под ручки).
- **«Маркер»** (`RD.marker`, `EP.marker`, кнопка `#rd-marker`, есть в панели PDF и EPUB): ведёшь пальцем или мышью, своя подсветка, системного меню нет. PDF: `mkDown/mkMove/mkUp`, буква под пальцем `tlCaret` по прямоугольникам кусков текстового слоя и ширине букв (без caretRangeFromPoint), `touchstart` гасится, листание и нажатия по краям выключены. EPUB: обработчики в документе главы с capture (`epMkDown/Move/Up`), касания не доходят до листания foliate (`guard`, в том числе touchend и touchcancel), буква `epCaret` (caretPositionFromPoint/caretRangeFromPoint, иначе ближайшая буква), в «Маркере» `touch-action: none` в стилях книги. У скана без текста (pdf-файл без has_text) кнопка `.off` и сообщение.
- Список: вкладка «Выделения» в карточке (фильтр цвета `UI.hlColor`, «Только с мыслями» `UI.hlThought`, «ещё» `UI.hlOpen`), `hlRow`, порядок `hlOrder` (формат, страница, процент); в «Заметках» фильтр «Выделения»; ссылка `noteHref` (`&hl=`).
- **EPUB** (`EP`, `epShow`, vendor/foliate): ссылка `?f=epub`, файл целиком `fetch` без кэша (`epFetch`, 429 → `rdPause`), `makeBook(File)`, скрипты книги не загружаются (`transformTarget` 'load' allow=false) и вырезаются из страниц вместе с on*-атрибутами и javascript: (`epClean`): у foliate iframe с allow-scripts и allow-same-origin. Листание foliate (свайп, кнопки, стрелки, нажатие по краям 28%), оглавление `book.toc`, ползунок `goToFraction`, шрифт 4 шага (`kn_epubFont`, `EP_FONT`), тема и шрифт Literata через `renderer.setStyles` (`epStyle`). Прогресс `relocate` → через 1,5 с и при уходе. Выделения через `addAnnotation` / `draw-annotation` (Overlayer.highlight, мигание Overlayer.outline), нажатие `show-annotation`. Подпись читателя: холст `#ep-mark` поверх страниц (`epMarkDraw`, тот же `rdWatermark`).
- **Форматы в клиенте**: `FORMATS`, `FMT_ORDER`, `VIEW`, `viewOf`, `isEpView`, `fmtLong` («DjVu, открывается как PDF»), `BOOK_ACCEPT`, `BOOK_RE`, `filesOfBook`, `fileOf`, `bookFormats`, `canRead`, `readOf(book, format)`, `readingOf`, `defaultFormat` (последний прочитанный, иначе PDF с текстом, иначе книга читалки EPUB с текстом, иначе DjVu с текстом, иначе любой читаемый), `scanFile`, `isScan`, `pageFileOf` (файл со страницами для заметок). Читалки знают свой формат: `RD.fmt` (pdf или djvu, ключ `book:ID:fmt`), `EP.fmt` (epub, fb2, mobi, azw3, txt): ссылка `?f=`, прогресс, цитаты и их загрузка (`format = {:f}`), «Заметка». Распознавание (правки 3.1, admin): `S.ocr`, `loadOcr` (раз в 6 с, пока открыт профиль или карточка и очередь не пуста), `ocrCardHTML`, `ocrSection` (профиль), `ocrAllAsk`, `ocrCancel`, `durText`, `aboutDur`; пометка `.ocr-note` «Текст распознан автоматически, возможны ошибки» у всех. `toast` создаёт `#toast` заново, если его унесла пересборка читалки. Карточка: переключатель `.fmt-seg` (`UI.cardFmt`), «Продолжить со с. N» / «Продолжить, N%», у DjVu «читалка позже». Обложка: пометка всех форматов, если их больше одного или формат не PDF. Меню книги: «Добавить формат» (`addFormat` → `addUploads(…, book)`), «Объединить с другой книгой» (`mergeBook`), «Убрать формат» (`removeFormat`). Окно после окна: `thenOpen` до `dlg.close()`.

## Этап 3: группы чтения
Несколько человек читают одну книгу. Всё видно только участникам группы; администратор приложения чужих групп не видит (правила по участию, роль admin в них не участвует), ему маршрут `GET /api/knigi/admin/groups-count` отдаёт только число.
- `groups`: name (до 100), description (до 1000), owner (relation без каскада, обязателен), invite_code (24 символа, уникальный, `newCode`), book (текущая книга, relation без каскада: книгу удалили → пусто). list/view: участник (`group_members_via_group.user ?= @request.auth.id`); update и delete: owner; create: нет (маршрут). Хук update оставляет прежними owner, invite_code, book (через API создатель меняет только название и описание). invite_code видит только создатель (`onRecordEnrich`).
- `group_members`: group, user (оба каскадно), last_seen (дата: когда человек последний раз открывал экран группы, точка «новое»), book_seen (какую книгу группы он уже видел: плашка «Группа начала новую книгу»). list/view: участник той же группы. Пишет только сервер.
- `group_books`: group (каскадно), book (без каскада), book_title, started_at, finished_at (пусто у текущей). Пишет только сервер. Название обновляется вместе с книгой.
- `group_plan`: group, gbook (relation на group_books, каскадно), format (pdf/epub), page (PDF), pct (EPUB), chapter (подпись), due (ГГГГ-ММ-ДД). Видят участники; create `@request.body.group.owner = @request.auth.id`, update/delete `group.owner = @request.auth.id`; хук `checkPlan`: только при `GROUP_PLAN`, gbook ставит сервер (текущая книга группы), формат есть у книги, страница в пределах, процент 0–100. При смене книги план «закрывается» сам: у новой group_books этапов нет. «Дошёл» считает клиент (`stageStatus`): прогресс формата этапа, другой формат сравнивается по проценту.
- `group_reads`: user, book (оба каскадно), day (ГГГГ-ММ-ДД по часам устройства, сервер принимает ±1 день от UTC, иначе свой), pages (json: открытые страницы PDF за день), pdf_n, epub_from (процент до первого сохранения за день, -1 = EPUB в этот день не читал), epub_to (самый дальний), epub_n; уникальная тройка (user, book, day). Видит только владелец. Пишет маршрут progress (`recordRead`, прямыми SQL), только если книга сейчас текущая хотя бы в одной группе человека, у всех, включая администратора, без лимита и журнала. Считается любое чтение книги группы, не только «Читать в группе».
- `note_comments`: note (каскадно), group (каскадно, ставит сервер = note.group), user (каскадно), text (до 2000, без оформления), edited. list/view: участник группы и `note.group = group` (запись убрали из группы → её комментарии не видны). create: от себя, хук `checkCommentCreate` (заметка в группе, вы участник); update: свой, хук `checkCommentUpdate` (только текст, ставит edited); delete: свой, под своей заметкой, любой у создателя группы.
- `notes.group`: в группе видна только своя заметка (kind note) или цитата (highlight); уроки нет. Хук `checkNoteGroup` (из `checkNote`): вы участник, книга записи = текущая книга группы (если group и book не менялись, правка старой групповой записи разрешена и после смены книги).
- Выход и исключение (`removeMember`): `UPDATE notes SET "group" = ''` у записей этого человека в этой группе (становятся личными), запись group_members удаляется, комментарии остаются (в клиенте автор не участник → «Бывший участник»). Удаление группы: каскадом участники, книги, план, комментарии; notes.group PocketBase очищает сам (relation без каскада).
- Маршруты (вход обязателен): `GET /api/knigi/group-config` → `{maxPerUser, maxMembers, plan}`; `POST /api/knigi/groups {name, description, book}`; `GET|POST /api/knigi/join/{code}`; `POST /api/knigi/groups/{id}/link|owner|remove|leave|book|seen`; `GET /api/knigi/groups/{id}/state?day&from` → `{book, day, from, members: {uid: {today: {pages, pct, read}, days: [...], pdf: {page, pages}, epub: {pct}}}}` (только текущая книга и только участникам: так участник видит чужой прогресс в книге группы, а collection reading по-прежнему видит только владелец); `GET /api/knigi/admin/groups-count`. Лимиты `checkLimit` и `checkRoom`. Фильтры и сортировка в users и groups ограничены безопасными полями, подписки живых обновлений с filter запрещены (как в «Молитвенном дневнике»).
- Клиент: экраны `VIEWS.groups`, `VIEWS.g` (шапка с участниками, `gBookCard`, `planBlock`, `todayBlock` с неделей кружками, `feedBlock`, прочитанные книги), `gPastBook`, `VIEWS.join`; окна `openNewGroup`, `openNextBook`, `openInvite`, `openMembers`, `openPlan`, `stageForm`, `pickNoteGroup` («Видно группе»); `gVisit` при заходе (запоминает прошлый last_seen в `UI.gPrev` для пометок «новое», зовёт `seen`, грузит `state` в `UI.gState`, не чаще раза в 30 с). Ссылка `/?group=КОД`: код в `kn_join` ({code, auto}); без входа после входа сразу `joinGroup`, с входом экран приглашения.
- Групповой режим читалки (`readerGroup`, `RD.group`, `EP.group`): адрес с `&g=`, только если человек в группе и группа читает эту книгу. Пометка в шапке `.rd-grp` (на телефоне строкой `#rd-gline`). В панели новой цитаты переключатель `.hp-g` (`HP.grp`, включён), «Заметка» передаёт `&g=` в редактор (`#ed-group`). «Показать цитаты группы» (`kn_grpHls`): `RD.ghls`/`EP.ghls` (чужие цитаты этой группы и формата), PDF рисует `.hl-mark.other` и `.hl-who`, EPUB аннотацией `other` (`epOtherDraw`: бледная заливка и кружок с буквой). Нажатие → `hpShowOther` → «Комментировать» (`#/note/ID?g=`). Перешли к чужой цитате из ленты (`&hl=`): она рисуется и без переключателя (`focusO`). «Назад» из читалки в групповом режиме ведёт в группу (`readerHistory`).
- Комментарии на экране заметки и цитаты (`commentsHTML`, `cmPaint` перерисовывает только их, когда открыт редактор), ссылки `linkify`, время `agoText`.

## Этап 4: сервер MCP для ИИ-помощников
Внутри PocketBase, те же служба и порт, без новых программ. Caddy менять не пришлось: `reverse_proxy` уже передаёт `/mcp`, `/oauth/*` и `/.well-known/*`. Файлы: `pb_hooks/mcp.pb.js` (маршруты), `mcp_lib.js` (OAuth, токены, настройки, ограничения частоты, журнал), `mcp_tools.js` (описания инструментов, их работа, JSON-RPC `rpc`, Markdown ↔ HTML), `mcp_page.js` (HTML страницы входа), `pb_public/oauth.js`, `oauth.css`, `oauth-theme.js`. Функции верхнего уровня `.pb.js` в обработчиках недоступны, поэтому всё в библиотеках.
- **Адрес** ресурса `APP_URL + /mcp` (`resourceUrl`, канонический: строчные схема и хост). Без `APP_URL` (у себя) берётся из запроса.
- **Метаданные**: `/.well-known/oauth-protected-resource` (и `/mcp` в конце): resource, `authorization_servers: [APP_URL]`, scopes `library offline_access`; `/.well-known/oauth-authorization-server` и `/openid-configuration` (и с `/mcp`): authorize, token, registration, S256, способы `none`, `client_secret_post`, `client_secret_basic`, `authorization_response_iss_parameter_supported`. CIMD не объявлен (Claude тогда идёт через DCR).
- **/mcp**: POST, JSON-RPC 2.0, ответ всегда JSON (SSE нет, сеансов `Mcp-Session-Id` нет), уведомления → 202, пакет (массив) тоже понимает. GET и DELETE → 405 с `Allow: POST`. Порядок проверок: `MCP_ENABLED` (503), `MCP_IP_ALLOW` по `e.realIP()` (403, строка «MCP: отклонён запрос с адреса» в журнале службы), Origin (если есть: свой сайт, сайты `MCP_REDIRECT_HOSTS`, localhost; иначе 403), 300 запросов в минуту с адреса, токен (`bearerGrant`: только заголовок `Authorization: Bearer`, в адресе не принимается; нет → 401 `WWW-Authenticate: Bearer resource_metadata=".../.well-known/oauth-protected-resource", scope="library offline_access"`, неверный → с `error="invalid_token"`; пользователь подключения должен оставаться admin). Версии протокола `PROTOCOLS`: 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05; initialize отвечает запрошенной, если знает, иначе 2025-11-25; неизвестный заголовок `MCP-Protocol-Version` → 400. Методы: initialize (с `instructions` по-русски), ping, tools/list, tools/call, пустые resources/prompts; остальное -32601, неизвестный инструмент -32602. Ошибка инструмента = `isError: true` с текстом для человека (`ToolError`).
- **Регистрация** `POST /oauth/register` (JSON, RFC 7591): адреса возврата только `https://` на хостах `MCP_REDIRECT_HOSTS` (точно или поддомен, без логина в адресе), иначе 400 `invalid_redirect_uri` и строка «Отклонён адрес возврата: …» через `console.log` (видно в `journalctl -u knigi`). Секрет выдаётся **всегда** (Perplexity без него обрывает подключение), проверяется на `/oauth/token` только у `client_secret_post`/`client_secret_basic` (принимается любым из двух способов); у `none` не требуется, но если прислан, должен быть верным. 30 регистраций в час с адреса. Клиенты без подключений старше суток удаляет уборка.
- **Вход** `GET /oauth/authorize` (`checkAuthorize`): клиент и адрес возврата из регистрации, иначе страница с ошибкой без перенаправления; `response_type=code`, PKCE S256 обязателен, `resource` (если есть) должен быть наш, иначе возврат с `error`. Страница: CSP без встроенных скриптов и стилей, `frame-ancestors 'none'`, данные в `<script type="application/json" id="oa-data">`. Скрипт берёт вход приложения из `localStorage.pocketbase_auth` (тот же ключ, что у SDK) и спрашивает `GET /oauth/me`; иначе форма → `POST /oauth/login` (`validatePassword`, ответ `$apis.recordAuthResponse`, сохраняется в `pocketbase_auth`, так что и приложение потом открыто; 10 попыток за 15 минут с адреса и на почту). «Разрешить»/«Отказать» → `POST /oauth/authorize` с ключом приложения: читателю 403 «доступно только администратору», отказ → `error=access_denied`, иначе одноразовый код (5 минут, `mcp_codes`) и адрес возврата с `code`, `state`, `iss`. Название на экране по хосту возврата (`serviceOf`): «Claude (claude.ai)», «ChatGPT (chatgpt.com)», «Perplexity (perplexity.ai)», незнакомый поддомен как есть.
- **Токены** `POST /oauth/token` (только форма `application/x-www-form-urlencoded`, 60 запросов в минуту с адреса, 20 неверных за 15 минут): authorization_code (код удаляется сразу, проверка клиента, redirect_uri, PKCE, роль admin) → создаётся подключение `mcp_grants` (service, host, scope) и пара токенов; refresh_token → старый удаляется (ротация, повтор = `invalid_grant`), новая пара, срок 60 дней заново.
